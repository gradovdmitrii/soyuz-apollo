# Союз-Аполлон

**Модели меняются. Ваша работа остаётся у вас.**

Союз-Аполлон (С-А) — файловый фреймворк: одна папка, общие правила для нескольких ИИ-клиентов и у каждого проекта свои правила и своя история Git.

## Зачем

- **Начать в одном клиенте, закончить в другом.** Проект не привязан к вендору: правила и результаты лежат в папке, а не в чате. Сменился клиент, закончилась подписка, недоступен провайдер — вы открываете ту же папку в другом клиенте и продолжаете.
- **Работать по подпискам, а не по API.** Если траты на API вам недоступны, а подписки есть, можно вести проекты в нескольких клиентах параллельно и не зависеть от одного. Это как работа с несколькими провайдерами, только скромнее и для частных случаев.
- **Держать результаты и решения в своих файлах.** Это обычный Markdown, который читает человек. Когда вокруг растёт поток сгенерированных документов, такие файлы помогают сохранить контроль: вы знаете, что решено, кем и почему.
- **Не воевать с клиентом.** С-А ложится на клиент как рабочая одежда: не спорит с его настройками и системными промптами, а работает рядом, через обычные файлы `AGENTS.md`.

## Для кого

- Инди-разработчики и исследователи, которые ведут несколько проектов при скромном бюджете.
- Те, кто ведёт «второй мозг» в Obsidian и привык к заметкам в Markdown.
- Студенты и все, кому удобно работать дисциплинированно: в одном проекте одна тема, в другом другая, и они пересекаются, только когда это нужно.

## Как устроено

```text
soyuz-apollo/
  AGENTS.md          корневые правила, их читает любой клиент
  .agents/           ядро: общие правила, шаблоны, справка
  projects/          ваши проекты, у каждого свой AGENTS.md и свой Git
  system-projects/   системные навыки и их данные
  port/              inbox/ от вас, outbox/ для вас, large-files/ крупные файлы
```

Архив лежит снаружи, рядом с установкой. Агенты открывают его только по вашей прямой команде.

Правила устроены как в федерации. В ядре общие правила: они действуют везде и их не ослабляет ни один проект. У каждого проекта свои локальные правила, но записаны они по единому стандарту, поэтому проект можно скопировать, унести и использовать отдельно.

Обслуживает всё это один небольшой инструмент, `sa.py`: он создаёт проекты, делает коммиты, проверяет установку и копирует её в резервную копию. Ему нужен только Python, внешних зависимостей нет.

## Что работает сейчас

Это ранний публичный выпуск, и мы называем его таким, какой он есть.

- **Платформа.** Windows 11, Python 3.11 или новее, Git с заданными `user.name` и `user.email`. Linux и macOS пока не поддерживаются.
- **Клиенты.** Antigravity, Codex, Claude Code, DeepSeek Harness, Hermes Agent. Статус каждого клиента и режима — проверено пробой или заявлено производителем — записан в [install/.agents/docs/compatibility.md](install/.agents/docs/compatibility.md). Читайте его как таблицу фактов, а не как обещание: «работает с любым агентом» мы не утверждаем.
- **Навыков пока нет.** В 0.3.0 есть каркас: структура папок, правила, `sa.py` и `update.py`. Системные навыки появятся в следующих выпусках.
- **Защита архива.** Правила в `AGENTS.md` — это соглашения. Замок на архиве ставят настройки разрешений клиента, и `sa.py` пишет их только для Claude Code и Codex. Проверено пробой только для Claude Code; в Codex настройки действуют, лишь если папка отмечена как доверенная, и пробой это пока не проверено. В остальных клиентах архив защищён лишь текстом правил; фрагменты настроек для них владелец применяет сам.
- **Память.** ИИ не помнит всё сам. Преемственность держат файлы проекта, прежде всего `handoff.md`.

## Быстрый старт

Создайте пустую папку с латинским путём в kebab-case вне OneDrive и вне Git (например, `C:\soyuz-apollo\`). В Codex отметьте её доверенной. Откройте ИИ-клиент в этой папке и отправьте промпт-визитку:

```text
Установи мне Союз-Аполлон в эту папку по инструкции из README: https://github.com/gradovdmitrii/soyuz-apollo
```

Если вы сами распаковали туда `soyuz-apollo-0.3.0.zip` со [страницы Releases](https://github.com/gradovdmitrii/soyuz-apollo/releases) (не `Source code (zip)`), отправьте: `Установи мне Союз-Аполлон по инструкции из README.md`.

Для обновления на месте (с 0.2.0 или 0.2.0-alpha.2) отправьте из чата вне установки или временно дав клиенту полный доступ:

```text
Обнови установку Союз-Аполлон в папке <путь установки> по инструкции из README: https://github.com/gradovdmitrii/soyuz-apollo
```

**Для агента (только `sa.py` и `update.py`, файлы ядра вручную не править):**
- **Установка.** Проверьте, что папка вне OneDrive и Git. Проверьте ZIP по `.sha256` и выполните установку по [инструкции](install/README.md). После записи цели первого проекта выполните `python sa.py commit projects/<name>/AGENTS.md -m "Set project purpose"`, затем `python sa.py doctor`. Попросите открыть новый чат.
- **Обновление.** Скачайте ZIP и `.sha256` с Releases, сверьте сумму и распакуйте вне установки. Выполните `verify`, `plan`, `apply` по [инструкции](install/README.md#9-обновление). При конфликте спросите владельца. При `RESTART-CHAT required` или `recommended` попросите открыть новый чат.

## Пример: как работа переходит из чата в чат

Вы вели проект `health` в одном клиенте и закончили сессию. Агент по вашей просьбе записал `projects/health/handoff.md`: цель, что сделано и что нет, ваши решения с датами, открытые вопросы и следующий шаг. Среди решений там стоит, например: «2026-11-03: без молочных продуктов — по рекомендации врача».

Через неделю подписка на тот клиент закончилась. Вы открываете другой клиент в той же папке и пишете: «Продолжаем проект health». Новый агент читает правила, затем `handoff.md` и видит не только следующий шаг, но и причину решения. У него есть записанное основание, и он может опереться на него, а не переспрашивать. Гарантии это не даёт: `handoff.md` лишь передаёт контекст, а следовать ему или нет, решает клиент. Историю изменений хранит Git проекта.

## Чем это не является

- Это не модель и не ИИ-ассистент: фреймворк не делает модель умнее и не расширяет возможности клиента.
- Это не облачный агент: файлы и `sa.py` работают на вашем компьютере. Что из них уходит модели и её провайдеру, решает ваш ИИ-клиент.
- Это не продукт безопасности: правила — соглашения, а защиту дают настройки клиента. Что фреймворк гарантирует, а что нет, описано в справке установки.
